# Stratio DLC

> A zero-code data replication engine that syncs data across domains and layers, executed as batch workflows in Stratio Rocket.

## 1. Overview

Stratio DLC (Data Layer Connector, deployed in GitOps as `dlc-entity`) replicates data across
domains and layers without requiring code — replication is defined and governed through Stratio
Data Governance and executed as batch workflows in Stratio Rocket. It syncs technical and
business data on a schedule, with consistency guarantees, publishes results back into Data
Governance collections, materializes views in Virtualizer, and can generate data lineage. It's
composed of the DLC Entity service (a stateless REST API, single-instance by design) plus a set
of Rocket workflows that do the actual data movement. It has no graphical UI of its own — it's
used via its REST API or Swagger.

In this fleet's sampled tenant configs, DLC is present but consistently **disabled** (either
`enabled: false` or fully commented out) — treat it as available-but-not-yet-turned-on rather
than actively running anywhere observed.

## 3. Dependencies

```
Stratio DLC (dlc-entity)
├─ Stratio PostgreSQL (pooled through PgBouncer)   (required — stores DLC's own metadata)
└─ Stratio Rocket                                    (required — executes DLC's batch workflows)
```

Also requires a Stratio Data Governance instance (versions 1.9–1.17 supported) for
configuration, though that relationship isn't wired as a formal chart dependency.

**Used by:**
- None found. No other component in this fleet's GitOps configs lists Stratio DLC as a
  dependency.

## 4. Flavors & Deployment Options

| Option | Choices | What changes |
|---|---|---|
| Authentication | JWT (default, enabled) \| mutual TLS (opt-in) | How clients authenticate to the DLC Entity API. |
| Connection pooling | on \| off | Whether its Postgres connection is pooled through PgBouncer — optional at install. |
| Data Governance Discovery Manager integration | on \| off (default on) | Whether DLC integrates with Data Governance's discovery manager. |
| Alertmanager integration | on \| off (default off) | Whether DLC sends alerts to Alertmanager. |
| Size | S \| M \| L | Resource sizing tier. |

## 5. Ingress / Exposed Endpoints

| Where | Protected by | What it's for |
|---|---|---|
| DLC Entity REST API + Swagger, at a configured virtual host or the internal service domain | JWT (default) or optional mutual TLS | Configuring and triggering data-replication workflows via API or Swagger — there is no graphical UI. |

## 6. Security & Secrets

| | |
|---|---|
| **Authentication** | A local admin account is created at install (default credentials; password only changeable via a direct database update); an auth token is obtained via a signin endpoint and used as a Bearer JWT on subsequent calls; JWT auth is on by default, mutual TLS is opt-in |
| **Credentials it holds** | Certificates generated by Stratio Command Center for secure communication with PostgreSQL, Rocket, and Data Governance |
| **Notable access controls** | A GoSec user is created for the service at install, with two auto-assigned policies — one for PostgreSQL access, one granting Rocket + Virtualizer access to manage and execute workflows under its own service identity; access to any other data store must be requested manually |
